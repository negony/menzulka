# Мензулка — архитектура и особенности реализации

Документ для разработчиков: как устроено приложение, какие решения приняты и
какие «грабли» уже пройдены. Пользовательское описание — в `README.md`,
инструкция для пользователя — `docs/Описание_программы_Мензулка.docx`.

## 1. Стек и окружение

- **Flutter** stable (Dart 3.13+), платформы — Android (`targetSdk 36`) и Windows x64.
- Локальная база — **drift** (SQLite); файлы фотографий и аудио — в каталоге
  документов приложения; версии проекта — в `<documents>/versions/`.
- Пакеты: `drift`, `sqlite3_flutter_libs`, `path_provider`, `path`, `image_picker`,
  `file_selector`, `file_picker`, `share_plus`, `archive`, `crypto`, `image`,
  `record`, `audioplayers`, `vector_math`, `uuid`.
- Установщик Windows — **Inno Setup 6** (`installer/windows_installer.iss`).

## 2. Структура

```
lib/
  models/       DXF-сущности, точки, нарисованные объекты, измерения, фото,
                аудио, история, версии, настройки привязок
  services/     DatabaseService (drift), DxfParser, SnapEngine, ProjectBundle
                (.abris), ProjectVersionService, AppPrefs, DxfExportService
  screens/      главный экран/чертёж, карточка точки, список точек,
                история измерений, история и версии, просмотр и правка фото
  widgets/      DxfViewer и отрисовка: холст, наложения, маркеры, привязки,
                лупа, инструменты, слои, нижняя панель режимов
  exporters/    DXF, ZIP с фотографиями
  utils/        геометрия (bulge-дуги), цвета ACI, кэш слоёв, фото, оверлеи
```

## 3. Данные

- Основные таблицы: `drawings`, `annotations`, `photos`, `audio_notes`,
  `measurements`, `drawn_objects`, `history_events`, `project_versions`.
- Фотографии и аудио хранятся файлами; в базе — пути и метаданные.
- **Идентичность чертежа — SHA-256 содержимого DXF**: при изменении файла
  создаётся новый проект, старые точки к нему не привязываются.
- Перенос проекта — только пакетом `.abris`; копировать базу SQLite вручную
  нельзя (в ней абсолютные пути к файлам).
- `clearProjectContent` удаляет точки/фото/заметки/измерения, сохраняя журнал.

## 4. Рендеринг DXF

- Свой парсер и своя отрисовка: LINE, LWPOLYLINE/POLYLINE (bulge-дуги), ARC,
  CIRCLE, ELLIPSE, SPLINE (приближение по точкам), POINT, TEXT/MTEXT,
  INSERT/BLOCK (рекурсивно, с аффинным преобразованием), SOLID/TRACE/3DFACE,
  RAY/XLINE, DIMENSION, LEADER.
- Кэш растровых слоёв для больших чертежей: перерисовка только при изменении
  масштаба или видимости.
- Границы чертежа считаются **устойчиво** — одиночные точки-выбросы не ломают
  вписывание.
- Блоки масштабируют толщину штриха — масштаб компенсируется при отрисовке;
  у INSERT с очень малым масштабом используется минимальный размер маркера.
- Встречаются сущности на слоях, которых нет в таблице LAYER — обходятся все
  кэши слоёв.

## 5. Привязки (OSNAP)

- Индекс привязок строится в мировых координатах DXF: вершины, точки, сегменты,
  дуги, эллипсы, лучи/прямые; для нарисованных объектов — тоже.
- Типы: конечная точка, узел, пересечение, перпендикуляр, касательная,
  ближайшая; настройки — в памяти (сбрасываются при перезапуске).
- Блоки раскрываются аффинно; слой берётся у корневого INSERT.
- Локальные координаты вьюера: `(x − minX, maxY − y)`; маркеры рисуются в
  экранном слое, поэтому не масштабируются вместе с чертежом.

## 6. Координаты X, Y, H

- Захват координаты — с типом привязки и источником («чертёж», «рисунок»,
  «чертёж+рисунок»).
- **H** берётся из самого объекта: Z из DXF (группа 30; у LW-полилиний — 38).
  Для нарисованных объектов H = 0, на пустом месте — «—».
- Объект для H определяется поиском ближайшего примитива к точке (скрытые слои
  учитываются) — `lib/services/dxf_elevation.dart`.

## 7. Рисование и правка объектов

- Инструменты: точка, полилиния, отрезок, прямая, круг, прямоугольник, облако,
  текст, размер; живые превью и привязки в процессе.
- Нарисованные объекты хранятся в БД (`drawn_objects`) со слоем, цветом ACI,
  толщиной, а для текста — высотой и углом.
- Выделение — только в режиме «Обзор»: перемещение, поворот двумя пальцами,
  масштаб текста щипком, поворот текста за уголок-ручку, изменение текста,
  удаление.
- На ПК: правая кнопка завершает рисование (полилиния/облако), средняя —
  панорама, колесо — масштаб; клики нерисуночными кнопками игнорируются.

## 8. Фотографии

- Фотографии добавляются камерой или файлом и копируются в каталог документов.
- Рисование поверх фото: примитивы хранятся в нормализованных координатах (0…1)
  относительно изображения, поэтому одинаково рисуются в превью и при
  сохранении в полном разрешении (PNG).
- Сохранение — «Заменить фото» или «Сохранить как новое»; после замены миниатюры
  обновляются принудительно (сброс кэша изображения + новый ключ элемента).
- В `.abris`: качество «Компактно» (1600 px, JPEG 80), «Полное», «Без фото».

## 9. Экспорт DXF (совместимость с AutoCAD)

- Экспорт ведётся на базе реального пустого чертежа AutoCAD 2013
  (`assets/empty.dxf`): полный набор стандартных таблиц (VPORT, LTYPE, LAYER,
  STYLE, VIEW, UCS, APPID, DIMSTYLE, BLOCK_RECORD), `*Model_Space` /
  `*Paper_Space`, корректные handle/owner/subclass и `$HANDSEED`.
- Имена слоёв пишутся «как есть» в UTF-8: escape `\U+XXXX` допустим для текста,
  но не для имён таблиц — иначе AutoCAD сообщает о недопустимом имени слоя.
- При создании слоя копируются коды 6/370/390/347/348 у существующего слоя.
- Записи TEXT содержат второй subclass-маркер `AcDbText`.
- `$EXTMIN`/`$EXTMAX` пересчитываются от фактической геометрии.
- Нарисованные объекты выгружаются нативными примитивами по слоям; опционально —
  точки (кружки и номера) и измерения (линии и подписи).
- Режим «DXF + фото (ZIP)» дополнительно кладёт `photos/`, `points.csv` и
  `README.txt`.

## 10. Пакет проекта `.abris`

- ZIP: `manifest.json` (чертёж, точки с описаниями, измерения, нарисованные
  объекты), `drawing.dxf`, `photos/<id>.<ext>`, `audio/<id>.m4a`.
- Аудио не перепаковывается (AAC уже сжат); импорт принимает пакеты и без аудио.
- Импорт восстанавливает точки, фото, заметки, измерения и нарисованные объекты,
  создавая новый чертёж.

## 11. История и версии

- События журнала пишутся из `DatabaseService` и `ProjectBundle` при изменении
  точек/фото/заметок/измерений и при экспорте-импорте.
- Версии проекта — снимки `.abris` в `<documents>/versions/`, не больше 20 на
  проект; поддерживаются создание, восстановление и удаление.

## 12. Сборка

### Windows

```bash
flutter build windows --release
iscc installer/windows_installer.iss        # Inno Setup 6
```

- Для `audioplayers_windows` нужен источник NuGet (`nuget.org` в
  `%APPDATA%\NuGet\NuGet.Config`), иначе CMake падает на установке пакета
  `Microsoft.Windows.ImplementationLibrary`.
- При нехватке RAM остановить Gradle-демон перед запуском
  (`cd android; .\gradlew --stop`).

### Android

```bash
flutter build apk --release
```

- `minSdk` — по умолчанию Flutter, `targetSdk 36`; параллелизм Gradle ограничен
  (`org.gradle.workers.max`, `parallel=false`) — иначе на слабой машине сборка
  падает с «Gradle build daemon disappeared».
- Release-APK подписывается тестовым (debug) ключом — для внутреннего
  тестирования; для публикации в магазине нужен собственный keystore.

## 13. Тесты и CI

```bash
dart format lib test tool
flutter analyze
flutter test
```

GitHub Actions (`.github/workflows/ci.yml`) выполняет проверку форматирования,
статический анализ и тесты при push в `main` и в pull request.
Тестовый DXF для привязок — `dart run tool/generate_snap_test_dxf.dart`;
синтетический проект с фото — `dart run tool/generate_test_bundle.dart`
(результаты в `build/test_data/`).

## 14. Известные ограничения

- Не поддерживаются: `HATCH`, `MLINE`, `MULTILEADER`, `IMAGE/WIPEOUT`,
  `ATTDEF/ATTRIB`, `REGION` (пропускаются).
- `SPLINE` рисуется приближением по опорным/подгоночным точкам (не точный NURBS).
- На общем виде подписи показываются выборочно (без перекрытий); полный текст —
  при приближении.

## 15. Полезные мелочи

- Не копировать `build/`, `.dart_tool/`, `.idea/`, `windows/flutter/ephemeral/` —
  ломаются символические ссылки плагинов. После переноса проекта: `flutter clean`,
  при необходимости удалить `windows/flutter/ephemeral`, затем `flutter pub get`.
- `file_selector` на Android: не проверять расширение по `file.name`.
- Иконки: `python tool/make_icons.py` пересоздаёт все размеры; adaptive foreground
  держится в safe zone (66/108), фон — `drawable/ic_launcher_background.xml`.
- `dist/` — артефакты сборки, в репозиторий не входит (`.gitignore`).
